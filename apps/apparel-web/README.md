# Apparel 인벤토리 화면

원본 인벤토리의 빈 목록, 분류 탭과 필터를 옮겼습니다. 실제 상품, 재고·권한·로그인과 저장 기능은 연결하지 않았습니다. 필터 선택지는 상품이 없는 경우의 원본 상태입니다. 실무에 사용할 수 없습니다.

개발 설정의 `/admin/inventory/shortages`는 같은 합성 재고의 부족 수량을 편집합니다. 저장은 이 탭의 세션 저장소에만 반영되며 실제 재고·로그인·권한과 연결하지 않습니다. 개발 설정이 없거나 운영 환경에서는 이 주소를 제공하지 않습니다.

`/admin/sales`는 원본의 빈 판매 목록과 검색 필터를 표시합니다. 실제 판매 조회, POS 동기화와 교차 검증은 연결하지 않았습니다. 합성 자료를 켜지 않으면 `수동 갱신`과 `교차 검증 즉시 실행`은 실패 알림을 표시합니다.

개발 환경에서 합성 자료를 켜면 판매내역에서 합성 POS·매장 티켓 두 건의 상세와 검색·필터를 확인할 수 있습니다. 실제 판매나 고객 데이터는 포함하지 않습니다.

같은 개발 설정의 판매내역에서 수동 갱신을 누르면 정해진 합성 POS 한 건이 현재 브라우저 탭에 추가됩니다. 반복해도 중복되지 않고 탭을 닫으면 사라집니다. 실제 POS 요청이나 매출 데이터 가져오기는 수행하지 않습니다. 교차 검증은 연결되지 않았습니다.

개발 환경에서 `VINTAD3E_APPAREL_FIXTURE=1`을 설정하면 합성 상품과 옵션을 목록에 표시합니다. 실제 상품이나 재고는 포함하지 않습니다. 상세에서 저장한 합성 수량은 현재 브라우저 탭의 세션 저장소에 남아 새로고침해도 유지되며 탭을 닫으면 사라집니다. 실제 재고를 입력하지 마세요. 실제 로그인과 서버 저장은 연결되지 않습니다.

합성 재고는 원본의 수량 검증과 저장 알림을 따르며, 저장하지 않은 변경이 있을 때 창을 닫거나 위치 탭을 바꾸면 확인합니다. GitHub 호스팅 Chrome 시험은 이 흐름을 합성 데이터로 확인합니다.

탭에 저장된 합성 재고가 손상됐거나 알 수 없는 항목을 담고 있으면 새 저장을 거부하고 기존 내용을 보존합니다.

같은 개발 설정의 `/admin/stats`에서는 합성 매출로 원본 통계 차트와 기간 조절을 확인할 수 있습니다. 실제 판매 데이터·상품 이미지·로그인·권한은 연결하지 않았으며 운영 환경에서는 이 주소를 제공하지 않습니다.

통계의 합성 매장 의류 판매 한 건은 판매내역과 같은 값과 한국 시간 날짜를 사용합니다. 통계에는 판매내역 샘플에 없는 과거·온라인 합성 값도 포함됩니다.

합성 로그인과 자료를 보려면 아래 실행 전에 같은 터미널에서 설정을 켭니다. Windows PowerShell에서는 `$env:VINTAD3E_APPAREL_FIXTURE = '1'`, macOS 또는 Linux에서는 `export VINTAD3E_APPAREL_FIXTURE=1`을 입력합니다. [전체 실행 순서](../../docs/first-run.md)를 함께 볼 수 있습니다.

Node 24와 Corepack을 준비해 루트에서 `corepack pnpm install --frozen-lockfile --ignore-scripts` 후 `corepack pnpm --filter @vintad3e/apparel-web dev`를 실행하고 `http://127.0.0.1:3826`을 엽니다.

상단의 `데이터 변경 이력` 메뉴(`/admin/audit`)는 원본의 빈 변경 이력과 필터를 표시하며 실행자 이름은 합성 명칭을 사용합니다. 실제 감사 기록과 로그인·권한은 연결하지 않았습니다.

개발 환경에서 합성 자료를 켜면 변경 이력 세 건의 실행자·기간·검색·정렬을 확인할 수 있습니다. 실제 직원이나 감사 데이터는 포함하지 않습니다.

개발 설정의 `/admin/inventory/graphics/TSHIRT-001`은 합성 디자인별 부족 수량과 옵션 편집을 표시합니다. 저장값은 같은 탭의 합성 재고와 공유되며 실제 재고와 연결하지 않습니다. 개발 설정이 없거나 운영 환경에서는 제공하지 않습니다.

`/admin/support`에서 용어집의 카테고리·검색·정렬을 사용할 수 있습니다. 회사 고유 위치와 몰 번호는 일반 표현으로 바꿨습니다.

개발 환경에서 `VINTAD3E_APPAREL_FIXTURE=1`을 설정하면 `/sign-in`에서 로컬 합성 세션을 만들 수 있습니다. 세션은 실제 인증이나 업무 권한을 제공하지 않습니다.

같은 설정의 `/confirmations/proposal-01`은 합성 제안의 불러오기·검토·확인 흐름을 표시합니다. 확인 결과는 화면에만 남으며 실제 상품 변경이나 승인 서버에는 연결되지 않습니다. 원본의 만료·오류 복구는 이관하지 않았습니다.

`/access-denied`는 합성 viewer 계정의 접근 거부 화면만 재현합니다. 이 화면은 다른 경로의 접근을 제한하거나 실제 권한을 판정하지 않습니다. 세션이 없는 상태에서 다시 로그인하면 홈으로 이동합니다.

## 로컬 재고 DB 검토

재고 화면의 CSV 가져오기와 SQLite 저장을 비교하기 위한 별도 시제품입니다. 개발 환경에서 `VINTAD3E_APPAREL_FIXTURE=1`, `VINTAD3E_APPAREL_LOCAL_DB=1`, `VINTAD3E_APPAREL_FIXTURE_ORIGIN=http://127.0.0.1:3826`을 설정한 뒤 앱을 실행하고 `/sign-in`에서 합성 로그인 후 `/admin/products`를 엽니다. CSV 양식은 재고 화면에서 내려받을 수 있습니다.

가져오기 전 확인하고 적용하면 `apps/apparel-web/.data/apparel-local-inventory.sqlite`에 보관되며 이전 가져오기를 한 번 되돌릴 수 있습니다. 기존 합성 재고 목록과는 별개입니다. 파일은 암호화되지 않고 합성 로그인은 실제 사용자 확인이 아닙니다. 백업·복구와 여러 직원의 권한은 구현하지 않았으므로 실제 직원·고객 정보나 실제 업무 자료를 넣지 마세요. 폴더와 백업의 접근 권한은 별도 설계가 필요합니다.
