# Timetable 화면

빈타제 Timetable 화면을 공개하기 위한 첫 단계입니다. 기존 화면의 출근부·근무시간표 전환, 빈 달력과 월 선택기, 출근부 필터와 비로그인 상태의 상단 헤더를 가져왔습니다. 로그인한 화면의 헤더, 하단 링크와 업무 동작은 원본 전체와 같지 않습니다. 합성 화면에는 실제 직원 정보를 입력하거나 업무에 사용하지 마세요.

원본의 PC·모바일 상단 메뉴도 헤더에 연결했습니다. 실제 관리자 권한은 확인하지 않으며, 개발용 관리자 설정을 켰을 때만 QR 관리 메뉴가 표시됩니다.

Node.js 24와 Corepack이 필요합니다. 저장소 루트에서 다음 명령을 실행합니다.

```sh
corepack pnpm install --filter @vintad3e/timetable-web...
corepack pnpm --filter @vintad3e/timetable-web dev
```

브라우저에서 `http://127.0.0.1:3824`를 엽니다. 종료는 터미널에서 Ctrl+C입니다.

기존 `/history`와 `/schedule` 주소도 원본처럼 출근부와 근무시간표로 이동하며 기간·정렬·월 선택을 전달합니다.

개발 환경에서만 `VINTAD3E_TIMETABLE_FIXTURE=1`을 설정하면 출근부에 합성 기록 21건을 표시합니다. 기본 필터는 최근 7일이며, 기간을 넓히면 원본처럼 10건씩 더 불러올 수 있습니다. 설정을 끄거나 운영 모드로 실행하면 이 합성 기록은 제공되지 않습니다. 이 기록은 실제 직원이나 로그인과 무관합니다.

같은 설정에서 별도 인증 API가 지정되지 않은 경우 로그인 버튼은 로컬 합성 세션을 만들며 `/confirmations/proposal-01`의 제안 불러오기·검토·확인과 `/auth/session-resume` 복귀 흐름에 사용할 수 있습니다. 이 세션은 실제 근태 권한을 부여하지 않고, 제안 확인은 화면 메모리에만 남습니다. 별도 인증 API가 지정되거나 합성 설정을 끄면 기존 인증 경로를 사용합니다.

같은 설정으로 근무시간표에도 월별 합성 일정 두 건과 읽기 전용 상세를 표시하고 합성 직원·장소를 선택할 수 있습니다. 합성 일정은 실제 일정·저장이나 권한 확인과 무관합니다.

관리자 합성 설정을 함께 켜면 합성 일정의 시간과 메모, 연결된 출퇴근 시각을 수정하거나 일정을 삭제할 수 있습니다. 시간표에 입력한 합성 출퇴근 기록은 관리자 출근부에서도 조회·수정·삭제하며 같은 탭의 시간표에 반영됩니다. 기존 출근부 샘플은 별도입니다. 변경은 현재 브라우저 탭에만 저장되며 실제 일정과 서버에는 반영되지 않습니다.

개발 환경에서 `VINTAD3E_TIMETABLE_FIXTURE=1`과 `VINTAD3E_TIMETABLE_FIXTURE_ADMIN=1`을 함께 설정하면 `/admin/kiosks`에서 합성 기기를 등록하고 `/kiosk`에서 30초마다 바뀌는 QR을 발급할 수 있습니다. `/scan`의 카메라가 QR을 읽으면 한 번만 사용할 수 있는 합성 출퇴근 기록이 만들어지며 `/admin/attendance`에서 정정하거나 무효 처리할 수 있습니다. 서버 메모리의 기기·QR·기록은 서버를 재시작하면 사라지고 현재 기기 식별자만 브라우저에 남습니다. 이 기록은 기존 시간표 합성 기록과 별도이며 실제 직원·인증·근태에는 연결되지 않습니다. 카메라 스캔은 카메라 권한이 필요합니다. 실제 직원 정보를 입력하지 마세요.

브라우저 자동 시험은 합성 비디오 프레임의 QR을 실제 스캐너 코드로 읽어 합성 출근 기록까지 확인합니다. 물리 카메라가 열리는 것은 별도로 확인했지만, 물리 카메라에 QR을 비춰 읽는 과정은 아직 확인하지 않았습니다.

개발 환경에서 `VINTAD3E_TIMETABLE_FIXTURE=1`과 `VINTAD3E_TIMETABLE_FIXTURE_SELF=1`을 설정하면 합성 직원 01의 일정과 같은 탭에 저장된 해당 직원의 합성 출퇴근 기록만 읽습니다. 시간표 상세와 출근부는 읽기 전용입니다. 관리자 설정을 함께 켜면 관리자 합성 화면이 우선합니다. 이 설정은 실제 로그인·권한이나 데이터 보호 기능이 아닙니다.

기존 Timetable 슬라이드 전환 컴포넌트와 해당 CSS를 보존했습니다. 이 저장소의 코드 이력에 사설 Git 이력이나 실제 직원·거래 자료는 포함하지 않습니다. 실제 인증 연결은 별도 작업입니다.

## 서버 조회 경로

`GET /api/timetable/history`와 `GET /api/timetable/shifts`는 서버에 설정된 `VINTAD3E_TIMETABLE_API_ORIGIN`의 로컬 Timetable API에 현재 세션 쿠키 하나만 전달합니다. 주소는 `http://127.0.0.1:<포트>` 형식만 허용하며, 요청을 보낸 사용자는 대상 서버를 지정할 수 없습니다. 일정 경로에는 `from`과 `to` UTC 시각이 필요하고 두 경로 모두 선택적 `cursor`를 받습니다. 쿠키가 없거나 올바르지 않으면 401, 접근 자격이 없으면 404, 설정·연결·응답 오류는 503입니다. 오류를 빈 기록으로 바꾸지 않으며 응답은 캐시하지 않습니다.

`GET /api/timetable/access`는 같은 방식으로 본인의 현재 역할만 확인합니다. 응답의 관리자 역할은 별도 쓰기 권한이나 쓰기 기능 활성화를 보장하지 않습니다. 이 경로는 아직 메뉴나 로그인 화면에 연결되지 않았습니다.

일정 경로에서 `include=attendance`를 지정하면 버전 14 API가 확인한 연결된 출퇴근 시각도 전달합니다. 연결 여부를 확인할 수 없거나 응답이 올바르지 않으면 503입니다.

서버 주소와 세션이 설정되면 출근부와 근무시간표에서 본인 기록을 읽습니다. 조회 결과는 최대 5,000건까지 페이지를 모두 확인한 뒤 표시하며, 더 많거나 읽기 실패·권한 거부가 발생하면 빈 목록 대신 원본 오류 상태를 표시합니다. 일정 상세에는 연결된 출퇴근 시각을 표시합니다. 직원 이름은 일반 명칭으로 표시하고 장소 선택지는 조회된 일정에서 만듭니다. 실제 인증 제공자와 HTTPS 프록시, 실제 사용자 경로 및 운영 환경은 검증하지 않았습니다.

가상 OIDC 제공자와 일회용 SQLite를 쓰는 통합 시험에서 로그인 후 본인 기록·일정 조회와 권한 회수를 확인했습니다. 기존 빈 화면을 실사용 데이터로 해석하면 안 됩니다.

`/auth/start`, `/auth/callback`, `/auth/logout`은 같은 로컬 API의 인증 시작·복귀·로그아웃을 전달합니다. 지정된 로컬 서버만 호출하고 인증에 필요한 쿠키만 전달합니다. 시작 시 안전한 내부 `next` 주소를 지정하면 그 로그인 요청에 묶어 복귀하며, 없거나 안전하지 않으면 홈으로 이동합니다. 로그아웃은 POST로만 가능하며 요청 출처는 인증 서버가 검증합니다. 합성 인증 제공자와 일회용 DB의 통합 시험 및 GitHub 호스팅 테스트 서버에서 경로를 검증했습니다. 로그인·로그아웃 버튼, 실제 인증 제공자와 HTTPS 프록시는 아직 연결하거나 확인하지 않았습니다.

개발 환경에서 `VINTAD3E_TIMETABLE_FIXTURE=1`과 `VINTAD3E_TIMETABLE_FIXTURE_ADMIN=1`을 함께 설정하면 합성 출퇴근 기록의 시각과 메모를 수정·삭제할 수 있습니다. 변경은 브라우저 탭의 세션 저장소에만 남으며 날짜가 바뀌면 초기화됩니다. 실제 권한·출퇴근 기록이나 서버 저장과는 연결되지 않으므로 실제 정보를 입력하지 마세요.

합성 출근부의 탭 저장 내용이 손상됐거나 알 수 없는 항목을 담고 있으면 새 수정을 거부하고 기존 내용을 보존합니다. 정상적인 이전 날짜의 합성 내용은 기존처럼 날짜가 바뀌면 초기화됩니다.

원본의 접근 거부 화면을 `/access-denied`에서 볼 수 있습니다. 다른 계정 버튼은 로컬 API의 로그아웃 경로를 호출하며 실제 인증 제공자 연결은 검증하지 않았습니다.

`/sign-in`은 원본 로그인 화면 구성과 기존 인증 시작 경로를 연결합니다. 회사 그림은 사용하지 않고 포털 자리에는 빈타제 표기를 사용합니다. 포털 이동은 개발 환경의 로컬 주소만 연결하며 실제 인증 제공자는 검증하지 않았습니다.

합성 관리자 설정을 켜면 원본의 `/admin/schedule` 주소가 선택한 달의 근무시간표로 이동합니다. 그 외에는 이 주소를 제공하지 않습니다. 실제 관리자 로그인이나 권한 검증과는 무관합니다.
