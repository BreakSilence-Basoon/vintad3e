# Timetable 화면

빈타제 Timetable 화면을 공개하기 위한 첫 단계입니다. 기존 화면의 출근부·근무시간표 전환, 빈 달력과 월 선택기, 출근부 필터와 비로그인 상태의 상단 헤더를 가져왔습니다. 로그인한 화면의 헤더, 하단 링크와 업무 동작은 원본 전체와 같지 않습니다. 실제 로그인 버튼, 일정 화면의 데이터 연결과 기록 저장은 없습니다. 실제 직원 정보를 입력하거나 업무에 사용하지 마세요.

원본의 PC·모바일 상단 메뉴도 헤더에 연결했습니다. 아직 로그인과 권한을 확인할 수 없어 관리자 메뉴는 표시되지 않으며 QR 관리 화면도 연결되지 않았습니다.

Node.js 24와 Corepack이 필요합니다. 저장소 루트에서 다음 명령을 실행합니다.

```sh
corepack pnpm install --filter @vintad3e/timetable-web...
corepack pnpm --filter @vintad3e/timetable-web dev
```

브라우저에서 `http://127.0.0.1:3824`를 엽니다. 종료는 터미널에서 Ctrl+C입니다.

기존 `/history`와 `/schedule` 주소도 원본처럼 출근부와 근무시간표로 이동하며 기간·정렬·월 선택을 전달합니다.

개발 환경에서만 `VINTAD3E_TIMETABLE_FIXTURE=1`을 설정하면 출근부에 합성 기록 21건을 표시합니다. 기본 필터는 최근 7일이며, 기간을 넓히면 원본처럼 10건씩 더 불러올 수 있습니다. 설정을 끄거나 운영 모드로 실행하면 기록은 제공되지 않습니다. 이 기록은 실제 직원이나 로그인과 무관하며, 아래 서버 조회 경로를 화면에 연결한 것은 아닙니다.

같은 설정으로 근무시간표에도 월별 합성 일정 두 건과 읽기 전용 상세를 표시하고 합성 직원·장소를 선택할 수 있습니다. 실제 일정 조회·저장이나 권한 확인은 연결되지 않습니다.

기존 Timetable 슬라이드 전환 컴포넌트와 해당 CSS를 보존했습니다. 이 저장소의 코드 이력에 사설 Git 이력이나 실제 직원·거래 자료는 포함하지 않습니다. 화면 연결과 실제 인증은 별도 작업입니다.

## 서버 조회 경로

`GET /api/timetable/history`와 `GET /api/timetable/shifts`는 서버에 설정된 `VINTAD3E_TIMETABLE_API_ORIGIN`의 로컬 Timetable API에 현재 세션 쿠키 하나만 전달합니다. 주소는 `http://127.0.0.1:<포트>` 형식만 허용하며, 요청을 보낸 사용자는 대상 서버를 지정할 수 없습니다. 일정 경로에는 `from`과 `to` UTC 시각이 필요하고 두 경로 모두 선택적 `cursor`를 받습니다. 쿠키가 없거나 올바르지 않으면 401, 접근 자격이 없으면 404, 설정·연결·응답 오류는 503입니다. 오류를 빈 기록으로 바꾸지 않으며 응답은 캐시하지 않습니다.

서버 주소와 세션이 설정되면 출근부 화면에서 본인 기록을 읽습니다. 기록은 최대 5,000건까지 페이지를 모두 확인한 뒤 필터링하며, 더 많거나 읽기 실패·권한 거부가 발생하면 빈 목록 대신 원본 오류 상태를 표시합니다. 일정 화면은 서버에 연결되지 않았습니다. 실제 인증 제공자와 HTTPS 프록시, 실제 사용자 경로 및 운영 환경은 검증하지 않았습니다.

다음은 화면 연결 이전 단계의 검증 기록입니다.

가상 OIDC 제공자와 일회용 SQLite를 쓰는 통합 시험에서 로그인 후 본인 기록·일정 조회와 권한 회수를 확인했습니다. 이 경로는 아직 화면에서 호출하지 않습니다. 브라우저 로그인 연결, 인증 제공자와 HTTPS 프록시 구성, 실제 화면 표시와 운영 환경은 검증하지 않았습니다. 기존 빈 화면을 실사용 데이터로 해석하면 안 됩니다.

`/auth/start`, `/auth/callback`, `/auth/logout`은 같은 로컬 API의 인증 시작·복귀·로그아웃을 전달합니다. 지정된 로컬 서버만 호출하고 인증에 필요한 쿠키만 전달하며, 복귀 성공 시 홈으로 이동합니다. 로그아웃은 POST로만 가능하며 요청 출처는 인증 서버가 검증합니다. 합성 인증 제공자와 일회용 DB의 통합 시험 및 GitHub 호스팅 테스트 서버에서 경로를 검증했습니다. 로그인·로그아웃 버튼, 실제 인증 제공자와 HTTPS 프록시는 아직 연결하거나 확인하지 않았습니다.
