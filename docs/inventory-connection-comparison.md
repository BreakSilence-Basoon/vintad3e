# 재고 연결 방식 비교

같은 Apparel 재고 파일을 세 방법으로 살펴보기 위한 별도 변경안입니다. 아직 기본 버전에 합쳐지지 않았고 실제 업무에 사용할 준비도 되지 않았습니다. 화면의 가상 로그인은 실제 사용자를 확인하지 않습니다. 세 방법 모두 실제 직원·고객·매출 정보는 넣지 마세요. CSV는 SKU, 상품명, 현재수량만 받으며 개인정보가 들어간 열은 거부합니다.

| 비교 | [파일 가져오기 #225](https://github.com/BreakSilence-Basoon/vintad3e/pull/225) | [한 컴퓨터의 SQLite #228](https://github.com/BreakSilence-Basoon/vintad3e/pull/228) | [별도 서버 #229](https://github.com/BreakSilence-Basoon/vintad3e/pull/229) |
| --- | --- | --- | --- |
| 난이도 | 낮음~중간. 파일을 고르고 확인한 뒤 화면에 표시합니다. | 중간. 파일을 확인한 뒤 컴퓨터 안의 DB 파일에 저장합니다. | 높음. 앱과 별도로 재고 서버를 실행하고 연결합니다. |
| 현재 보관 | 화면에만 남으며 페이지를 벗어나면 사라집니다. 기존 재고 목록은 바뀌지 않습니다. | 한 컴퓨터의 `.data` 폴더에 남습니다. 기존 재고 목록과는 별개입니다. | 현재 시제품은 서버 메모리에만 남고 서버를 끄면 사라집니다. 기존 재고 목록과는 별개입니다. |
| 위험과 권한 | 파일을 열 수 있는 사람이 내용을 볼 수 있습니다. 열 이름만으로 모든 개인정보를 찾아내지는 못합니다. | DB 파일은 암호화되지 않았습니다. 컴퓨터 계정으로 파일에 접근할 수 있는 사람을 구분해야 합니다. | 시제품은 같은 컴퓨터에만 열리고 실제 인증·암호화가 없습니다. 인터넷에 공개하거나 실제 가게 서버로 쓰면 안 됩니다. |
| 백업 | 원본 파일을 직접 따로 보관해야 합니다. | 자동 백업·복구는 아직 없습니다. 원본과 DB를 안전하게 보관하고 복구를 검증하는 기능이 필요합니다. | 시제품에는 백업이 없습니다. 실제 서버를 쓰려면 별도 백업·복구와 담당자가 필요합니다. |
| 여러 사람 | 한 사람의 화면에만 표시됩니다. | 같은 컴퓨터의 파일을 사용하지만 직원별 권한과 안전한 동시 사용은 구현하지 않았습니다. | 시제품은 같은 컴퓨터의 서로 다른 브라우저에서 공유합니다. 여러 컴퓨터에서 안전하게 쓰는 기능은 별도 구현이 필요합니다. |
| 나머지 8개 앱 | 앱별 3~7 개발일, 단순 합계 24~56일. | 앱별 2~4 개발주, 단순 합계 16~32주. | 앱별 4~8 개발주 이상, 단순 합계 32~64주 이상. |

기간은 한 개발자가 각 앱에 별도 연결을 만든다는 거친 가정이며, 공통 인증·보안·백업, 실제 운영과 법률 검토는 포함하지 않습니다. 필요한 앱만 선택하면 총 작업량은 달라집니다. 각 변경안의 설명에서 실행 조건과 검사를 확인하세요. 세 변경안은 서로 대안이므로 동시에 합치는 것을 전제로 하지 않습니다.

데이터를 실제로 보관하기 전에는 접근할 사람, 보관 기간, 백업과 복구 방법을 가게에 맞게 정하고 확인해야 합니다. 가게마다 필요한 개인정보처리방침과 이용약관은 직접 준비해야 합니다. 더 넓은 선택 기준은 [가게 데이터 연결 방식](store-data-options.md)을 보세요.
