# 빈타제 API를 가상 자료로 실행해 보기

> 이 문서는 실험용 API를 확인하기 위한 안내입니다. 완성된 업무 앱의 설치 안내가 아닙니다. Ledger와 Timetable의 API만 내 컴퓨터에서 시험합니다. 실제 직원·고객·거래 정보, 실제 비밀번호나 접속 토큰을 넣지 마세요.

## 준비할 것

- 명령을 입력할 터미널과 인터넷 연결이 필요합니다. 아래 준비 단계에서는 Git과 Node.js 24, Corepack으로 실행하는 pnpm 10.11.0을 확인합니다.
- 빈타제 저장소의 루트 폴더에서 명령을 실행합니다. 루트 폴더는 `package.json`과 `scripts` 폴더가 함께 있는 곳입니다. 저장소에 포함된 `scripts/local-api-fixture.cjs`와 `scripts/fixture-process.cjs`가 필요합니다.
- 아래 설치 명령은 공개 커밋만 담은 격리된 Linux 환경에서 빈 캐시와 공개 패키지 저장소를 사용해 검증했습니다. `--ignore-scripts`로 설치 단계 스크립트를 실행하지 않은 시험입니다. Windows에서의 새 설치는 별도 확인이 필요합니다.
- 로컬 포트 43131과 43132를 사용합니다. 이미 다른 프로그램이 사용 중이면 시험을 중단하고 해당 프로그램을 확인하세요.

## 0. 저장소와 프로그램 확인

이미 빈타제 저장소를 내려받았다면 터미널에서 그 폴더로 이동하고 아래 버전 확인으로 넘어갑니다. 처음이라면 터미널을 열고, 새 폴더를 만들 위치에서 다음을 한 줄씩 실행합니다.

```sh
git --version
git clone https://github.com/BreakSilence-Basoon/vintage.git
cd vintage
```

첫 명령에서 버전 대신 명령을 찾을 수 없다는 오류가 나오면 [Git 설치 안내](https://git-scm.com/install/)를 확인하고 다시 시작하세요. `git clone`은 현재 위치에 `vintage` 폴더를 만듭니다. 같은 이름의 폴더가 이미 있다면 내용을 지우거나 덮어쓰지 말고, 기존 저장소로 이동하거나 다른 빈 위치에서 시작하세요. `cd vintage`는 그 폴더 안으로 이동하는 명령입니다.

이제 같은 터미널에서 다음을 한 줄씩 실행합니다.

```sh
node --version
corepack pnpm --version
```

첫 결과가 `v24.`로 시작하고 두 번째 결과가 `10.11.0`인지 확인합니다. Corepack은 처음 실행할 때 필요한 pnpm을 내려받을 수 있으므로 인터넷 연결이 필요합니다. `node` 또는 `corepack`을 찾지 못하거나 버전이 다르면 설치 단계로 넘어가지 말고 [Node.js 설치 안내](https://nodejs.org/en/download)와 [Corepack 안내](https://github.com/nodejs/corepack#readme)를 확인하세요. 이 저장소의 pnpm 버전은 루트의 `package.json`에 지정돼 있으므로, 버전 확인도 저장소 루트에서 실행합니다.

## 1. 시험에 필요한 패키지 설치

저장소 루트에서 아래 명령을 실행합니다. 실행 결과에 오류가 나오면 다음 단계로 넘어가지 마세요.

```sh
corepack pnpm install --frozen-lockfile --ignore-scripts --filter @vintage/ledger-api... --filter @vintage/timetable-api...
```

설치할 때는 공개 패키지 저장소에 접속합니다. 저장소에 접근할 수 없거나 설치가 실패하면 오류를 확인하고 다음 단계로 넘어가지 마세요.

## 2. 가상 서버가 시작되는지 확인

```sh
node scripts/local-api-fixture.cjs --check
```

스크립트가 가상 자료만 들어 있는 새 임시 폴더를 만들고, 공개 검증 키와 각 API의 새 빈 SQLite 데이터베이스를 준비합니다. 새로 만든 키의 개인키는 파일로 저장하지 않습니다. Ledger와 Timetable을 각각 내 컴퓨터에서만 시작한 뒤 확인하고 종료합니다. 사용 중인 DB 파일이나 실제 서비스에는 연결하지 않습니다.

두 서버가 시작됐다는 안내와 함께 인증 없는 확인 요청의 응답이 Ledger 400, Timetable 404로 나오면 이 가상 기동 확인이 끝난 것입니다. 이 확인은 로그인 성공이나 업무 기능 전체가 작동한다는 뜻이 아닙니다.

## 3. 잠시 실행해 두기

```sh
node scripts/local-api-fixture.cjs
```

두 서버가 시작되면 터미널을 열어 둡니다. 중지할 때는 그 터미널에서 **Ctrl+C**를 누릅니다. Windows에서 실제 콘솔의 Ctrl+C 동작은 아직 확인하지 못했습니다. 정상 종료를 기다린 뒤 반응하지 않는 이 시험이 시작한 자식 프로세스만 강제 종료할 수 있습니다. 이 API에는 사용할 수 있는 웹 화면이 아직 없으며, 브라우저에 주소를 입력해도 업무 앱이 나타나지 않습니다.

가상 자료 폴더의 위치는 실행할 때 표시됩니다. 자동으로 지우지 않습니다. 실패해도 새 폴더나 파일이 남을 수 있으니 표시된 경로와 내용을 확인하기 전에는 재사용하거나 정리하지 마세요. 실제 자료를 이 폴더에 넣지 마세요.

## 이 시험으로 확인하지 못하는 것

이 예시는 외부 로그인 제공자에 연결하거나 접근 토큰을 발급하지 않습니다. 실제 사용자 인증, 브라우저 로그인, 권한 관리, HTTPS 배포, 백업·복구와 실제 업무 처리는 아직 검증되지 않았습니다. 인터넷에 서버를 공개하거나 이 예시를 운영 환경으로 사용하지 마세요.

참고: [Ledger API 실험](../apps/ledger-api/README.md), [Timetable API 실험](../apps/timetable-api/README.md). Windows에서의 전체 실행과 새 컴퓨터의 설치 과정은 별도로 확인해야 합니다.


## 가상 직원 예제

`examples/timetable/staff.json`에는 사용자가 지정한 가명 10명과 임의의 표시용 직급이 들어 있습니다. 모두 합성 데이터이며 실제 직원이나 계정과 연결하지 않습니다. 직급은 화면 표시용일 뿐 권한을 부여하지 않습니다.

공개 TimeTable 직원 저장 스키마는 사업장 ID와 직원 ID만 저장하며 이름과 직급은 저장하지 않습니다. `examples/timetable/timetable-projection.mjs`는 명시한 가상 사업장 ID와 직원 ID만 변환합니다. 기존 API fixture에 이 예제는 자동으로 추가되지 않으며 실제 데이터베이스에 쓰지 않습니다. 다른 앱에서 사용하기 전에는 각 앱의 데이터 형식과 연결 방식을 따로 확인해야 합니다.
