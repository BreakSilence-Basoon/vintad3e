# 앱별 실행을 위한 준비

[처음 실행하기](first-run.md) · [다른 앱 화면 실행하기](local-apps.md)

화면을 가상의 자료로 살펴보는 방법은 위 안내를 따르세요. [Timetable API](../apps/timetable-api/README.md)와 [Ledger API](../apps/ledger-api/README.md)는 별도 실험 단계입니다. 실제 가게 자료를 안전하게 처리하는 업무용 설치는 아직 제공하지 않습니다.

- `apps/`: 각각의 업무 앱
- `packages/`: 두 앱 이상이 필요로 하거나 별도 검증이 필요한 공통 기능
- 각 앱은 자신의 의존성과 실행 명령, 환경 변수 이름, 저장·인증 방법을 설명합니다.

Node.js 24와 Corepack으로 pnpm 10.11.0을 사용합니다. `corepack pnpm test`는 가상 패키지의 선택 실행과 오프라인 설치를 확인하고, Timetable과 Ledger의 실험 API를 각각 별도 작업 공간에 선택 설치해 가상 자료로 로컬 검사를 실행합니다. 이미 채워진 패키지 저장소를 이용한 시험이며, 새 사용자의 인터넷 설치나 실제 로그인·운영 보안을 검증하는 것은 아닙니다.

## README 편집

README의 ‘만든 사람의 말’은 개발자가 확정한 원문입니다. AI 에이전트는 이 부분을 수정·요약·번역·이동하지 않습니다. README의 다른 부분은 자유롭게 고칠 수 있습니다. `corepack pnpm test` 또는 `node scripts/check-founder-note.mjs`로 확정본을 검사합니다.

## 이름 변경 시 확인

상품명의 영문 표기는 문장 첫머리에서도 항상 소문자 `vintad3e`로 씁니다.

영문 이름은 `vintad3e`입니다. 이전 실험 설정을 사용하던 경우 각 API 안내서의 `VINTAD3E_` 환경 변수 이름과 `@vintad3e/` 패키지 이름으로 설정을 다시 맞춰야 합니다. 브라우저 로그인 쿠키 이름도 바뀌어 기존 실험 세션은 다시 로그인해야 합니다. 데이터베이스 자체를 이름 변경 명령으로 지우거나 재생성하지 마세요.

앱이 추가되면 해당 앱의 정확한 패키지 이름과 공통 의존성을 명시하고, pnpm의 `--filter <패키지명>...`으로 필요한 패키지를 선택합니다. 의존성 설치 범위와 실행 명령은 앱마다 독립 환경에서 검증하고, 해당 앱 안내서에 실제 동작을 기록합니다. 없는 패키지는 성공으로 오해하지 않도록 `--fail-if-no-match`를 사용합니다. [pnpm 필터 공식 문서](https://pnpm.io/filtering)
